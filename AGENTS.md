# Работа с Portfolio

Перед изменениями прочитайте PROJECT.md и PLAN.md, проверьте git status и актуальную задачу пользователя. Эти файлы сохраняют контекст между машинами и сессиями; не запускайте полный редизайн только по наличию плана.

## Принципы

- Мобильный интерфейс проектируется первым; основные размеры проверки 360, 390 и 430 px. Затем landscape и desktop.
- Сохраняйте статический HTML/CSS/JavaScript, пока требования не обоснуют смену стека. Пути должны работать под /Portfolio/.
- Применяйте доступный frontend-design для композиции; web-design-guidelines для ревью; webapp-testing для браузерных сценариев, если установлены. Не утверждайте, что skill установлен или тест пройден, без проверки.
- Не выдумывайте показатели, отзывы, клиентов или роль Лизы. Сохраняйте оригиналы скриншотов; не дорисовывайте доказательства результатов.
- Нативный скролл сохраняет ожидаемое направление. Не перехватывайте жесты всей страницы ради эффекта.
- Анимация должна быть видна во время чтения соответствующего блока. Контент доступен без JS и при reduced-motion; без вспышек и обязательного движения.
- Галерея поддерживает увеличение и перемещение изображения, явное закрытие, корректный фокус и возврат позиции страницы. Проверяйте конфликты pan/swipe.
- Не делайте функции доступными только через hover. Проверяйте контраст, фокус, масштаб текста, доступные названия и области нажатия.
- Версии внешних библиотек фиксировать; сохранять лицензии. Не добавлять зависимости без конкретной пользы.

## Проверка и передача работы

- Сначала воспроизведите существенный дефект, затем проверяйте исправление тем же сценарием.
- Для галереи и motion нужны браузерные проверки; чтение исходников не заменяет их. Эмуляция WebKit не считается проверкой настоящего iPhone.
- Измерения скорости сопровождайте профилем устройства/сети; не заявляйте полевые метрики по лабораторному тесту.
- Не затирайте чужие изменения. Не изменяйте конфигурацию деплоя по предположениям.
- В конце этапа обновляйте PLAN.md и PROJECT.md: изменения, проверки, открытые вопросы и конкретный следующий шаг.
- Пользователь разрешил реализацию и установку skills. Сохраняйте исходные палитру и семейства шрифтов. У VR-клуба и ресторана сравнения только кнопочные; у автосервиса — скролл-анимация со статичным fallback. Не смешивайте способы управления в одном сравнении. Публикация пока не выполнялась; следуйте актуальному разрешению пользователя.
